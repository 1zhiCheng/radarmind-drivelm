\begin{abstract}
本报告记录 DriveLM-nuScenes v1.1 六视角视觉语言模型的完整复现过程。原始 DriveLM 项目以 Graph Visual Question Answering（GVQA）表达自动驾驶中的感知、预测和规划推理，但论文模型与挑战基线依赖的部分权重和训练实现并未形成可直接在当前服务器运行的现代开源流水线。本项目保留官方数据抽取逻辑、六相机输入、QA 标识与提交格式，使用 Qwen2.5-VL-3B-Instruct 作为基础模型，对注意力层和 MLP 投影层实施 LoRA 监督微调。

数据由 696 个有标签场景按 scene token 的 SHA-256 哈希确定性拆分为 619 个训练场景和 77 个开发场景，分别包含 26,095 与 3,355 条问答；官方无标签 val 包含 149 个场景、15,480 条问题。模型完成 6,524 次更新，最终 LoRA 可训练参数为 18,576,384，占总参数的 0.4923\%。开发集 3,355 条回答全部生成并匹配，离线 Overall Exact Match、Token-F1 与 ROUGE-L 分别为 44.26\%、73.33\% 和 71.59\%，多选准确率为 81.46\%。结果显示模型对二元推理和运动状态判断表现较好，但规划、精确对象 ID 接地和长链关注图仍是主要瓶颈。
\end{abstract}

\section{结论先行：测试指标究竟如何得到}
本项目报告的“测试指标”更准确地说是\textbf{本地场景隔离开发集指标}。计算链路如下：
\begin{enumerate}
  \item 从带答案的 \path{v1_1_train_nus.json} 经 DriveLM challenge 官方脚本抽取基础 QA。
  \item 对每个 scene token 计算 SHA-256 哈希；哈希桶小于 0.1 的整个场景进入 dev，其余进入 train。同一场景不会同时出现在两侧。
  \item 得到 619 个训练场景、26,095 条训练 QA，以及 77 个未参与 SFT 的开发场景、3,355 条开发 QA。
  \item 使用最终 LoRA adapter 对 \path{qwen_dev.jsonl} 的六张同步相机图像逐条生成答案，输出 \path{dev_predictions.json}。
  \item 以唯一 ID 对齐预测和参考答案。3,355 个参考 ID 全部匹配，coverage 为 100\%。
  \item 运行 \path{evaluate_offline.py}，逐样本计算规范化 Exact Match、Token-F1、ROUGE-L，再对 Overall 和各 task 取算术平均；A/B/C/D 问题另算准确率。
\end{enumerate}

\section{研究背景与复现目标}
\subsection{DriveLM 与 Graph VQA}
DriveLM 将自动驾驶理解组织为图视觉问答：由重要对象识别开始，沿对象状态、未来关注关系、碰撞风险和安全动作形成依赖链。与单一检测或分割任务相比，这一表示能够同时考察：
\begin{itemize}
  \item \textbf{Perception：}识别对当前决策重要的车辆、行人和交通元素，并给出对象状态；
  \item \textbf{Prediction：}判断对象类别或状态，并按照自车下一位置给出有序关注对象；
  \item \textbf{Planning：}回答候选动作、碰撞动作与安全动作；
  \item \textbf{Behavior：}从多选项预测自车转向和速度行为。
\end{itemize}
DriveLM 数据建立在 nuScenes 与 CARLA 等自动驾驶数据之上。本报告聚焦 DriveLM-nuScenes v1.1 的纯视觉六相机复现，不把尚未接入本轮 SFT 的 nuScenes radar 数据计入模型输入。

\subsection{为什么采用 Qwen2.5-VL}
原论文使用 BLIP-2 路线，challenge 发布的历史基线依赖受限的 LLaMA-1 权重与旧版适配器。为获得可下载、可训练、可部署的现代基线，本项目采用 Qwen2.5-VL-3B-Instruct：
\begin{itemize}
  \item 原生支持多图输入，可把六个同步相机视角作为独立视觉输入；
  \item 3B 量级适合单张 48\,GB A6000 或 32\,GB 级 GPU 上进行 LoRA 微调；
  \item 具有统一图像—文本对话模板，可直接生成自由文本和 A/B/C/D 答案；
  \item PEFT/LoRA 训练只更新不足 0.5\% 的参数，便于快速迭代和保存 checkpoint。
\end{itemize}

\subsection{复现目标与非目标}
本轮目标是打通并实测：
\[
\text{DriveLM 标注}\rightarrow\text{六相机 JSONL}\rightarrow
\text{LoRA SFT}\rightarrow\text{dev 生成}\rightarrow
\text{离线评估}\rightarrow\text{official val 输出}.
\]
本轮不声称逐参数复现论文 BLIP-2，也不声称获得官方 challenge 排名；未进行 camera-only 与 radar-fusion 的受控消融，亦没有多随机种子统计。

\subsection{确定性场景级拆分}
拆分函数为：
\[
b(s)=\frac{\mathrm{int}(\mathrm{SHA256}(s)_{0:8},16)}{2^{32}-1}.
\]
若 $b(s)<0.1$，scene $s$ 进入 dev；否则进入 train。该策略避免同一约 20 秒场景的相邻关键帧泄漏到训练集和开发集。随机种子 42 主要用于保持官方多选项抽取与转换结果可重复。

\section{模型与微调方案}
\subsection{基础模型结构}
本地模型配置显示，Qwen2.5-VL-3B 使用 32 层视觉编码器，视觉 hidden size 为 1280，patch size 为 14，spatial merge size 为 2；视觉输出映射到 2048 维。语言模型包含 36 层、hidden size 2048、16 个 attention heads 和 2 个 key/value heads，最大位置长度为 128K。

每张图设置最大 75,264 pixels，即 $96\times28\times28$；这是一项显存预算上限，实际视觉 token 数随缩放后的图像尺寸变化。六视角在 processor 中保持为六个独立图像输入。

\begin{figure}[H]
  \centering\includegraphics[width=\textwidth]{model_architecture.png}
  \caption{六视角 Qwen2.5-VL-3B LoRA 模型结构与训练位置。}

\subsection{LoRA 注入}
LoRA rank $r=8$，缩放系数 $\alpha=16$，dropout 为 0.05，bias 不训练。注入模块为：
\[
\{q,k,v,o\}_{\mathrm{proj}}\cup
\{\mathrm{gate},\mathrm{up},\mathrm{down}\}_{\mathrm{proj}}.
\]
可训练参数 18,576,384，总参数 3,773,199,360，占比 0.4923\%。最终 adapter 权重约 74.4\,MB，显著小于基础模型。

\section{推理与评估方法}
\subsection{开发集生成}
最终 adapter 对 \path{qwen_dev.jsonl} 全量生成。processor 使用与训练一致的六图顺序和像素预算；decoder 采用确定性生成（\code{do\_sample=False}），最多生成 256 个新 token。多选题若输出以 A--D 开头，则规范化为单个大写字母。最终 reference、prediction 和 matched ID 均为 3,355，coverage 为 100\%。

\subsection{文本规范化}
评价前把预测与参考答案转为小写，去除非英文字母/数字字符，并把连续空白压缩为单空格：
\[
N(x)=\mathrm{collapse}\bigl(\mathrm{regex}_{[^a-z0-9]}(
\mathrm{lower}(\mathrm{strip}(x)))\bigr).
\]
该规范化会忽略大小写和标点差异，但不会处理同义词。例如“decelerate”与“slow down”仍被视为不同 token。

\subsection{Exact Match}
\[
\mathrm{EM}(p,r)=\mathbb{I}\left[N(p)=N(r)\right].
\]
长答案只要对象顺序、类别或措辞不同，就可能 EM 为 0，因此 EM 对 important-object 和 notice-graph 尤其严格。

\subsection{Token-F1}
将规范化文本按空格分词，并按词频多重集计算重叠数 $o$：
\[
P=\frac{o}{|p|},\quad R=\frac{o}{|r|},\quad F_1=\frac{2PR}{P+R}.
\]
每条样本计算后，在 Overall 或任务组内取算术平均。这不是把全部 token 汇总后的 micro-F1。

\subsection{ROUGE-L}
对预测 token 序列与参考 token 序列求最长公共子序列长度 $L$：
\[
P_L=\frac{L}{|p|},\quad R_L=\frac{L}{|r|},\quad
\mathrm{ROUGE\mbox{-}L}_{F1}=\frac{2P_LR_L}{P_L+R_L}.
\]
本实现是无外部依赖的 LCS-F1，不包含 stemming 或同义词扩展。

\subsection{多选与对象结构指标}
参考答案规范化后若为 A/B/C/D，则进入多选准确率，共 890 条。错误分析还用正则表达式抽取 \code{<cN,CAM\_*,...>} 中的对象序号与相机名，忽略坐标，累计计算结构 precision、recall 和 F1。该指标只衡量简化的对象 ID/视角绑定，不等价于检测框 AP。

\subsection{对象 ID 接地}
简化对象结构累计统计为：true positive 810、预测对象键 2,615、参考对象键 2,468，对应 precision 30.98\%、recall 32.82\%、F1 \metric{31.87\%}。这解释了为何 important objects 的语言 Token-F1 达 70.63\%，Exact Match 却为 0：模型往往能生成合理的场景描述，但对象编号、相机方向与精确实例绑定不稳定。

\subsection{结果解读}
\begin{enumerate}
  \item \textbf{分类式问题较强。}二元推理与运动状态多选均超过 95\%，说明模型已学会常见问答模板与粗粒度场景状态。
  \item \textbf{自由文本语义可用，但严格 EM 偏低。}候选动作 Token-F1 76.69\%，EM 仅 11.59\%，反映合理同义表达和参考答案模板差异。
  \item \textbf{Planning 是当前核心瓶颈。}Planning overall Token-F1 61.76\%，碰撞推理仅 48.98\%；错误中常见“应减速或停车”与“保持速度”的混淆。
  \item \textbf{单关键帧存在行为歧义。}Behavior 准确率 68.52\%，仅凭同步单帧难以可靠判断自车速度和转向趋势，后续需要时序帧或 ego state。
\end{enumerate}

\section{局限性与下一阶段}
\subsection{当前局限}
\begin{itemize}
  \item 缺少 base model 未微调基线，不能仅凭当前实验严格量化 LoRA 带来的净提升；
  \item 只有一个 seed 和一个主要配置，没有误差条或显著性检验；
  \item 恢复 checkpoint 未保存 optimizer state，训练轨迹在第 3,000 步存在优化器状态断点；
  \item 第 1--3,000 步的逐步 loss 日志不可用，当前只能审计恢复段累计平均值；
  \item 六图视觉预算较低，对小行人、车辆细分类和像素坐标接地不利；
  \item 当前经过评估的 DriveLM 模型是纯视觉模型，尚未把 nuScenes radar token 纳入同一受控实验；
  \item 连续视频中的 bounding box 来自标注，仅作为解释层，不代表模型具备检测框回归能力。
\end{itemize}

\subsection{推荐实验路线}
\begin{enumerate}
  \item 在完全相同的 77-scene dev 上补跑 base、LoRA-v1、hard-task-v2 三组；
  \item 保存 optimizer/scheduler state 与逐步原始 loss，至少运行 3 个 seed；
  \item 提高视觉预算或对重要对象做 ROI crop，重点观察 object-ID F1；
  \item 引入连续两到五帧和 ego speed/yaw，改善 behavior 与 collision reasoning；
  \item 在相同 QA、split 和 evaluator 下增加 radar point/BEV encoder，进行 camera-only、radar-only、camera+radar 消融；
  \item 将安全动作输出约束为结构化 schema，并在 CARLA 中加入 safety shield 后进行闭环评估。
\end{enumerate}
